## 2026-11-15 — One category list for Layers and Ranglijst; Herkomst per regio with Nederland; Criminaliteit back

- **Why the crime layers vanished.** No dataset or group was removed: the Veiligheid section was still generated. Commit 971c61e made the wide Layers dropdown CSS `columns: 2` with a `max-height` and `overflow-y: auto`. Multi-column content that is taller than the box does not scroll down; it spills into extra columns to the right, outside the 420px box. Once the herkomst layers grew the list (v0.25.0 postcode groups, v0.28.0 world regions: ~30 extra entries), the last sections, Veiligheid and Voorzieningen, landed in those invisible columns. Fix: a two-column CSS grid (`.layers-dropdown.open { display: grid }`) that scrolls vertically; a test forbids `columns:` on the dropdown again.
- **One category definition.** `DATASET_GROUPS` in `modules/datasets.js` is the single list, used by the Layers dropdown (app.js), the Uitleg panel and the Ranglijst pickers. Each category has a `headline`: Woonscore → woonscore, Bevolking & huishoudens → population, Leeftijd → pop65plus, Herkomst → originDutchPct (Nederland), Criminaliteit → crimeRate (Misdrijven totaal), Opleiding → highEdu, Welvaart & wonen → avgIncome, Voorzieningen → distSupermarket. Bevolking was split into Bevolking & huishoudens, Leeftijd and Opleiding so the category names match what people look for. `categoryHeadline(cat, scope)` falls back to the first layer in scope when the headline has no data there; a category without layers in a scope is not offered.
- **Criminaliteit** is the category name (was Veiligheid; the wizard theme keeps the name Veiligheid). Order: Misdrijven totaal, the ten police 47018NED kinds (Rotterdam wijk/buurt only), then per km² and omgeving. Nederland scope has only the total (83648NED per gemeente), so the category shows there with one layer.
- **Herkomst = Nederland + world regions.** The separate indelingen (Europa excl. NL, buiten Europa, buitenland geboren, the ten postcode country groups) moved to group `herkomstDetail` with `layer: false`: their data stays for the wizard, area modal and Uitleg, but they are no layer and no Ranglijst column. Old links: `RETIRED_LAYERS` maps each id to the nearest region layer (country group → its region; Europa excl. NL → West-Europa; buiten Europa → Zuid-Amerika, Rotterdam's largest group via Suriname; buitenland geboren → Nederland), applied in `sanitizePatch` (hash, dashboard buttons) and in the share-link and Ranglijst rank/sort decoding.
- **Nederland as a region** reuses `originDutchPct` (exists for gemeente, wijk and buurt) instead of a new `hr_nederland` key: no new data path. It is `NEDERLAND_REGION` / `LAYER_REGIONS` in herkomst-regio.js, deliberately not in `REGIONS`, which stay the migration-background partition used by the file format and `regionGap`. Caveat: per gemeente the Nederland layer comes from 70072ned (2023), the regions from 85458NED; the test checks Nederland + regions + Onbekend ≈ 100% within the regio file itself (`nederlandShareOf`).
- **Ranglijst "Rangschik op"** is now two selects, Categorie (Totaalscore first) and Onderdeel (the category's layers in scope, headline marked "(totaal)"). Picking a category ranks on its headline; `rankKeyForCategory` is the pure rule. The share format is unchanged (`rank=<key>`, `sort=<col>.<dir>`); the sort column pattern now allows `_` so region columns can be shared, which only widens what decodes.

- **Rank wording** (`modules/area-detail.js`, pure, `tests/area-detail.test.js`): peers are all areas of the same level with a value (nulls excluded, so "van 76" can be less than the 91 buurten); ties share a place (competition ranking). - **Reference value = peer median**, not a population-weighted city average: the median of the 91 buurten (or wijken) is what the rank and percentile are measured against, and it is not pulled by the outliers. Percentages differ in procentpunten, everything else in % of the median.

- **One pure module `modules/scale.js`:** `buildScale(values, { method })` returns `colorFor`, `classOf`, `isOutlier`/`outlierSide`, `classes`, `breaks`, `median`, `q1`, `q3`, `lo`/`hi` (fences) and `outliers` counts. Map (Rotterdam wijk/buurt and the Nederland tiers), legend, Ranglijst bars/chips and dashboard bars/dots all use it, built from exactly the set on screen (scope, level/tier and crime mode), so every toggle rebuilds it. `interpolateColor` moved there (re-exported by overlays.js), as did `NO_DATA_COLOR` (re-exported by rotterdam.js).

Outliers keep their class fill (the top or bottom class) and add a solid red border `#ef4444`, weight 2.5: solid reads better than dashed on small buurt polygons over the dark basemap. ## 2026-11-15 — Ranglijst view

- **Score = percentile rank 0–100 within the shown list** (Rotterdam wijken, buurten, provinces or gemeenten), ties share the mid-rank; one value or all-equal scores 50. `higherIsBetter: false` inverts it, `null` (population, 65+, herkomst) is shown with a heat bar but left out of the overall score. Overall = mean of the available scores; "2/3" = scores used / scored datasets that have data anywhere in the list. Logic in `modules/ranking.js` (pure, `tests/ranking.test.js`).
- **Ranks use competition ranking** (1-2-2-4). Rows with no overall score (no data, or only neutral datasets) are unranked ("—") and sink to the bottom, sorted by name. Missing values sort last in both directions.

## 2026-11-15 — Woonscore (Epic W1, v0.18.0)

- **Engine** `modules/score.js` (pure, no imports): percentile 0..1 within peers (mid-rank, same rule as `ranking.js`), preference `higher`/`lower`/`target` (Gaussian with sd = tolerance, shifted to reach exactly 0 at ±2 tolerances), `filter` flags an area (`filtered`) and never drops it, score = 100 × Σ w·f / Σ w over factors with data, null below 60 % weight coverage, `explain()` = plus/minus factors by impact 100·w·(f − 0.5)/Σw (above or below the peer middle).
- **log1p:** a percentile rank is unchanged by a monotone transform, so log1p before the percentile (plan §1) changes nothing; the `log` flag is kept and matters only for `target` distances. Shrinkage works on raw rates.
- **Shrinkage** only for buurten (parent = wijk) and only on rates per 1.000 (`RATE_KEYS`: crime, bijstand): rate' = w·rate + (1 − w)·wijk, w = n/(n + 300), applied to every buurt (proper empirical Bayes; large buurten barely move). The "weinig inwoners" badge shows when n < 300, i.e. when the wijk weighs more than the buurt. Wijken and NL gemeenten are not shrunk. The shown values stay the raw rates; only the score uses the shrunk ones.
- **Standaard preset** (`modules/presets.js`): a theme weight (35/20/25/10/10) is split evenly over the theme's metrics that have data among the peers; a theme without data is dropped and the rest renormalise. So NL gemeenten (crimeRate, avgIncome, highEdu) get veiligheid 35/65, welvaart 20/65, opleiding 10/65 instead of the crime metric collapsing to one fifth of 35. `ownerOccupiedPct` counts as a mild plus here although it is neutral as a layer.
- **Gelijk gewogen preset** = weight 1 for every directional `inOverall` dataset, no shrinkage, no coverage threshold; tested to equal the Ranglijst Totaalscore. The Totaalscore code (`ranking.scoreAreas`, `area-detail.overallRank`) is left as it is rather than rerouted, so its crime-mode (`abs`) behaviour and the used/possible counter stay unchanged.
- **Where the score is computed:** `areas.js` adds `values.woonscore` and the full result (`area.woonscore`) to wijken and buurten at load; `app.js` adds `woonscore` to the province and gemeente rows after each CBS merge. The Woonscore always uses rates, also in crime mode Absoluut. It is a normal dataset (`woonscore`, group "Score", unit `score`, `inOverall: false`), so map, legend, Uitleg, dashboard and Ranglijst pick it up; the Ranglijst ranks and shows the score itself (not its percentile).
- **Default layer and deep links:** `DEFAULT_STATE.dataset` is `woonscore`. The hash now carries `dataset=` when it is not the Woonscore, so a link to another layer keeps it; a hash without `dataset` opens on the Woonscore. Old links (which never had `dataset`) open on the Woonscore instead of Bevolking.
- **Not in W1:** the Ranglijst breakdown column per theme, the `#score=<preset>` hash and a preset switcher (W3).

## 2026-11-15 — Freeze on the switch to Nederland, app loader, MapLibre image warnings (W13)
- **Report (operator):** zoomed in on a Rozenburg buurt in the Rotterdam scope, then switched to "Nederland": the map locked up for about 30 s.
- **Cause: O(n²) percentile ranks.** `percentileRanks` (`modules/score.js`, Woonscore) and `percentileScores` (`modules/ranking.js`, Ranglijst) counted "below/equal" with a linear scan over all peers for every value. Harmless for 12 provincies, 342 gemeenten or Rotterdam's ~90 buurten, but the NL drill-down scores all 14,729 NL buurten as peers: 14,729² ≈ 217 M comparisons per factor, about ten factors, twice (personal preset + Standaard). The clicked buurt stays in `state.area`; on the scope switch `focusNederlandArea(BU…)` drills into it, which loads and scores every NL buurt (`loadNlLevel('buurt')`), and the postcode/bouwjaar files landing afterwards rescore them again (`rescoreNlAreas`). The stack in the console (setView → maplibre jumpTo) was only where the last sample fell, not the cost.
- **Fix:** sorted peers + binary search (`countBelow`), O(n log n), identical results (unit test against the linear scan, ties, nulls and the log transform). `loadNlLevel` yields to the main thread between decoding and scoring, so no single task holds both.
- **Measured** (node 22, data/nl, same machine): `loadNlLevel('buurt')` (wijken cached) 12,749 ms → 298 ms; `rescoreNlAreas()` 13,601 ms → 175 ms; `withWoonscore` on 14,729 buurten alone ≈ 185 ms (the longest single task now); decode + omgeving of the buurten 170 ms. Before ≈ 26 s main-thread block for the sequence, matching the ~30 s seen.
- **Not changed:** the drill layers already show one gemeente at a time, so no canvas renderer (it would also drop the SVG elements `addKeyboardNav` makes focusable). The scope switch still carries a Rotterdam wijk/buurt in `area` into the Nederland drill-down (existing deep-link behaviour); now fast, kept.
- **Loader (`modules/loader.js`):** `showLoader(label)` / `hideLoader()` (reference-counted), `setLoaderProgress(p)` (clamped 0..1 into `--progress` on `#app-loader`, null = `is-indeterminate`), `withLoader(label, fn)` waits two animation frames (timer fallback for background tabs) so the overlay is painted before the work. The map gets `map-busy`. Used on boot until the first scope is drawn (Nederland: provinces coloured; at most 20 s), on every scope switch, and on the first load of the NL wijk or buurt data in the drill-down. Markup and CSS come from the house-style branch (w14); without `#app-loader` every call is a no-op.
- **Console noise:** MapLibre "Image 'wood-pattern' / 'circle-11' could not be loaded" is answered by a `styleimagemissing` handler that adds a 1×1 transparent image (`patchMissingImages`, `modules/map.js`). "Expected value to be of type number, but found null" comes from OpenFreeMap style filter expressions evaluated on tile data, not from our layers: left as is.
