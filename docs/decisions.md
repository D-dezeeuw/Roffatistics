# Decisions

## 2026-11-15 — Rotterdam mode (v0.10.0)

- **Default scope is Rotterdam.** A topnav dropdown switches to "Nederland", which keeps the pre-0.10 province → gemeente → buurt tiers unchanged. The scope is stored in `localStorage` (`roffatistics.scope`) and mirrored in the URL hash (`#scope=…&view=…&area=…`); the hash wins over storage.
- **Wijk/buurt data: CBS 85984NED** (Kerncijfers wijken en buurten 2024). 85618NED (2023) has a few more income cells (Pernis, Nieuw Mathenesse) but older numbers everywhere else; one table keeps the scale consistent. Column keys live in `WIJK_COLUMNS` (`modules/areas.js`).
- **No wijk crime data.** 85984NED has no registered-crime columns, so `crimeRate` is null for every wijk/buurt and the map shows them all in the neutral "geen data" colour. Police wijk crime (table 47018NED) would be a separate fetch; not in scope.
- **Percentages are computed** from counts: `highEdu` = hbo/wo ÷ (three education levels), `pop65plus` and `nonWesternPct` (herkomst buiten Europa) ÷ inwoners. `avgIncome` is the household standardised income (`GemGestandaardiseerdInkomen_83`), not the gemeente table's employee income; both are ×€1,000.
- **Geometry is pre-cached** in `data/rotterdam_{gemeente,wijken,buurten}.geojson` (65 KB together, coordinates rounded to 5 decimals) instead of a runtime PDOK WFS call: GitHub Pages serves it with the app and the mask/fit never wait on PDOK. Regenerate with `node scripts/build-rotterdam-geo.mjs`.
- **Every area is always drawn.** Areas without a value share `NO_DATA_COLOR` (#4b4658); the legend shows a "geen data" swatch in Rotterdam mode. Wijk and buurt levels each get their own min/max scale. Buurten replace the wijk fill from zoom 13; wijk outlines stay on top.
- **Mask** = one Leaflet polygon: world ring plus every ring of GM0599 (evenodd fill makes the city a hole), in its own pane under the overlays at 0.85 opacity. `maxBounds` = city bounds + 15 %, `minZoom` = fit zoom − 1.
- **State bus** (`modules/state.js`): `setState` emits `state-change` on `document` with `{state, prev, changed, source}`; listeners use `source` to avoid echoing their own changes (map clicks set `area` with source `map`, other sources make the map zoom to the area).
- **Compare in Rotterdam mode** pins wijken/buurten instead of gemeenten, using the same panel slots.

## 2026-11-15 — Area search

- **Own matcher, no dependency** (`modules/fuzzy.js`, pure). Names and queries fold to lowercase ASCII letters and digits (NFKD, diacritics stripped); punctuation, apostrophes and hyphens only mark word edges, so "s-gravenhage", "'s Gravenhage" and "zuidholland" all match. Tiers: exact 1000 > prefix 900 > word-start 700 > substring 500 > one typo 300 (whole word) / 250 (half-typed word) > subsequence 100–150. Typos (Damerau/OSA distance ≤ 1 over all query tokens) only for queries of 4+ characters; substring needs 2+, subsequence 3+.
- **Ties:** inside a tier shorter names rank first, except when the query ends on a word boundary ("kralingen" in "Kralingen West"): then no length penalty, and the level order decides. Level order follows the scope: Rotterdam scope wijk > buurt > gemeente > provincie, Nederland scope gemeente > provincie > wijk > buurt.
- **Aliases** for gemeenten/provincies live in `ALIASES` (Den Haag, The Hague, Den Bosch, Friesland, …); an alias hit shows as "'s-Gravenhage (Den Haag)" with the alias highlighted.
- **Results are labelled, not regrouped:** each row carries its level ("Wijk · Rotterdam", "Buurt · Rotterdam · <wijk>", "Gemeente", "Provincie") so the list keeps one ranking and arrow keys walk it in order. At most 12 rows.
- **Selection goes through the state bus** with source `search`: Rotterdam areas → `{scope:'rotterdam', area}`, gemeenten/provincies → `{scope:'nederland', area}`, GM0599 → `{scope:'rotterdam', area:null}` plus a fit to the city. Dashboard view switches to the map first (one frame later the zoom runs on a visible map). List view calls `highlightArea(code)` from `modules/list.js` via a guarded dynamic import, 400 ms later when the scope changed so the list can re-render. Re-selecting the current area clears `area` first so the zoom still runs.
- **Nederland focus** = `focusNederlandArea(code)` in `modules/overlays.js`: fits a provincie below the gemeente tier and a gemeente on the gemeente tier (zoom 10–12), then opens its panel. `app.js` calls it on an `area` change in Nederland scope and after a scope switch to Nederland, so `#scope=nederland&area=GM0344` deep links now zoom too.
- **Recent searches:** last 5 picks in `localStorage` (`roffatistics.recentSearches`), shown when the input is empty; storage errors are ignored.
