# Decisions

## 2026-11-15 — Rotterdam mode (v0.10.0)

- **Default scope is Rotterdam.** A topnav dropdown switches to "Nederland", which keeps the pre-0.10 province → gemeente → buurt tiers unchanged. The scope is stored in `localStorage` (`roffatistics.scope`) and mirrored in the URL hash (`#scope=…&view=…&area=…`); the hash wins over storage.
- **Wijk/buurt data: CBS 85984NED** (Kerncijfers wijken en buurten 2024). 85618NED (2023) has a few more income cells (Pernis, Nieuw Mathenesse) but older numbers everywhere else; one table keeps the scale consistent. Column keys live in `WIJK_COLUMNS` (`modules/areas.js`).
- **No wijk crime data in 85984NED.** Superseded on the same day: wijk crime now comes from police table 47018NED (see Dashboard below). Buurten keep `crimeRate` null.
- **Percentages are computed** from counts: `highEdu` = hbo/wo ÷ (three education levels), `pop65plus` and `nonWesternPct` (herkomst buiten Europa) ÷ inwoners. `avgIncome` is the household standardised income (`GemGestandaardiseerdInkomen_83`), not the gemeente table's employee income; both are ×€1,000.
- **Geometry is pre-cached** in `data/rotterdam_{gemeente,wijken,buurten}.geojson` (65 KB together, coordinates rounded to 5 decimals) instead of a runtime PDOK WFS call: GitHub Pages serves it with the app and the mask/fit never wait on PDOK. Regenerate with `node scripts/build-rotterdam-geo.mjs`.
- **Every area is always drawn.** Areas without a value share `NO_DATA_COLOR` (#4b4658); the legend shows a "geen data" swatch in Rotterdam mode. Wijk and buurt levels each get their own min/max scale. Buurten replace the wijk fill from zoom 13; wijk outlines stay on top.
- **Mask** = one Leaflet polygon: world ring plus every ring of GM0599 (evenodd fill makes the city a hole), in its own pane under the overlays at 0.85 opacity. `maxBounds` = city bounds + 15 %, `minZoom` = fit zoom − 1.
- **State bus** (`modules/state.js`): `setState` emits `state-change` on `document` with `{state, prev, changed, source}`; listeners use `source` to avoid echoing their own changes (map clicks set `area` with source `map`, other sources make the map zoom to the area).
- **Compare in Rotterdam mode** pins wijken/buurten instead of gemeenten, using the same panel slots.

## 2026-11-15 — Ranglijst view

- **Score = percentile rank 0–100 within the shown list** (Rotterdam wijken, buurten, provinces or gemeenten), ties share the mid-rank; one value or all-equal scores 50. `higherIsBetter: false` inverts it, `null` (population, 65+, herkomst) is shown with a heat bar but left out of the overall score. Overall = mean of the available scores; "2/3" = scores used / scored datasets that have data anywhere in the list. Logic in `modules/ranking.js` (pure, `tests/ranking.test.js`).
- **Ranks use competition ranking** (1-2-2-4). Rows with no overall score (no data, or only neutral datasets) are unranked ("—") and sink to the bottom, sorted by name. Missing values sort last in both directions.
- **Columns appear only for datasets with at least one value** in the list, so `crimeRate` shows up by itself once wijk crime data lands; hidden datasets are named in the note above the table.
- **"Rangschik op"** defaults to Totaalscore. Picking a dataset sets `state.dataset` (source `list`); later dataset changes from the map are followed only while a dataset (not Totaalscore) is selected. Ranking on a neutral dataset orders by raw value, high first.
- **Sticky columns:** rank, name and score are sticky on the left at fixed widths (CSS variables, narrower under 640 px); the dataset columns scroll horizontally inside `.list-table-wrap`, never the page.
- **Nederland scope** ranks provinces (default) or gemeenten once their CBS rows are loaded; `app.js` passes them with `setNationalRows()`. Names come from `getAreaIndex()`. Without rows the view offers a switch to Rotterdam.
- **Search contract:** `highlightArea(code)` (modules/list.js) awaits the current render, switches level when the code is a buurt/wijk (or gemeente/province) on the other level, scrolls the row to the centre (`behavior: 'auto'` under reduced motion) and flashes `.is-flash` for 2.2 s. The list also does this for `state.area` changes from other sources while visible.
## 2026-11-15 — Area search

- **Own matcher, no dependency** (`modules/fuzzy.js`, pure). Names and queries fold to lowercase ASCII letters and digits (NFKD, diacritics stripped); punctuation, apostrophes and hyphens only mark word edges, so "s-gravenhage", "'s Gravenhage" and "zuidholland" all match. Tiers: exact 1000 > prefix 900 > word-start 700 > substring 500 > one typo 300 (whole word) / 250 (half-typed word) > subsequence 100–150. Typos (Damerau/OSA distance ≤ 1 over all query tokens) only for queries of 4+ characters; substring needs 2+, subsequence 3+.
- **Ties:** inside a tier shorter names rank first, except when the query ends on a word boundary ("kralingen" in "Kralingen West"): then no length penalty, and the level order decides. Level order follows the scope: Rotterdam scope wijk > buurt > gemeente > provincie, Nederland scope gemeente > provincie > wijk > buurt.
- **Aliases** for gemeenten/provincies live in `ALIASES` (Den Haag, The Hague, Den Bosch, Friesland, …); an alias hit shows as "'s-Gravenhage (Den Haag)" with the alias highlighted.
- **Results are labelled, not regrouped:** each row carries its level ("Wijk · Rotterdam", "Buurt · Rotterdam · <wijk>", "Gemeente", "Provincie") so the list keeps one ranking and arrow keys walk it in order. At most 12 rows.
- **Selection goes through the state bus** with source `search`: Rotterdam areas → `{scope:'rotterdam', area}`, gemeenten/provincies → `{scope:'nederland', area}`, GM0599 → `{scope:'rotterdam', area:null}` plus a fit to the city. Dashboard view switches to the map first (one frame later the zoom runs on a visible map). List view calls `highlightArea(code)` from `modules/list.js` via a guarded dynamic import, 400 ms later when the scope changed so the list can re-render. Re-selecting the current area clears `area` first so the zoom still runs.
- **Nederland focus** = `focusNederlandArea(code)` in `modules/overlays.js`: fits a provincie below the gemeente tier and a gemeente on the gemeente tier (zoom 10–12), then opens its panel. `app.js` calls it on an `area` change in Nederland scope and after a scope switch to Nederland, so `#scope=nederland&area=GM0344` deep links now zoom too.
- **Recent searches:** last 5 picks in `localStorage` (`roffatistics.recentSearches`), shown when the input is empty; storage errors are ignored.
## 2026-11-15 — Dashboard view

- **Plain SVG strings, no chart library.** `modules/dashboard.js` builds each chart as an SVG string sized to the measured card width and redraws on a `ResizeObserver` width change, so text stays at 10–11 px on a phone instead of scaling with a viewBox. Pure maths and formatting live in `modules/dashboard-data.js` (unit-tested).
- **Rotterdam figures are population-weighted.** KPI and "Ø Rotterdam" lines: `population` is the sum of the wijken; every other dataset is the mean weighted by inhabitants over wijken that have a value. For `crimeRate` this equals total misdrijven ÷ total inhabitants of those wijken. WOZ and income would ideally be weighted by dwellings/households; inhabitants is close enough and needs no extra column.
- **Missing values stay visible.** Bars sort high → low; wijken without a value follow as grey "geen data" rows (by name). The scatter leaves them out and says how many.
- **Active dataset card comes first**, outlined in orange; the scatter card follows (default X inkomen, Y WOZ). Clicking a bar or dot sets `{area, view: 'map'}` with source `dashboard`; app.js defers `focusArea` one frame when the view changes in the same patch, so `fitBounds` runs after the map is visible.
- **Nederland scope shows a message plus a "Naar Rotterdam" button** instead of a province dashboard: the view compares wijken, and province rows live inside app.js.
- **Wijk crime: CBS dataderden 47018NED** (Politie, "Geregistreerde misdrijven; soort misdrijf, wijk, buurt, jaarcijfers", 2012–2025) on `https://dataderden.cbs.nl/ODataApi/odata`, `SoortMisdrijf = '0.0.0 '` (totaal), `Perioden = '2025JJ00'` (last full year), wijken `WK0599*`. Rate = misdrijven ÷ 85984NED inhabitants (2024) × 1,000; the one-year gap between counts and population is accepted. Wijken under 1,000 inhabitants (the port and industrial wijken) get `null`: a few dozen residents against hundreds of incidents gives meaningless rates. Fetched in parallel with the kerncijfers, cached in sessionStorage, best-effort (a failure leaves `crimeRate` null). Code: the delimited crime block in `modules/areas.js` (`buildWijkCrimeUrl`, `crimeRatePer1000`, `mergeWijkCrime`).

## 2026-11-15 — View polish (v0.12.0)

- **Dark-on-dark root cause:** the `@media (prefers-reduced-motion: reduce)` block at the end of the Ranglijst CSS was never closed, so every rule after it (search modal and the whole Dashboard block, including `.dash-svg text { fill }` and the tooltip) only applied to visitors with reduced motion. Everyone else got unstyled SVG text (black by default) and an unstyled tooltip. All `var(--x)` were defined. Fixed by closing the block; `tests/style.test.js` now asserts balanced braces, that the view blocks are top-level rules, that every `var(--x)` in `style.css` and `modules/*.js` is defined, and AA contrast of the text tokens.
- **Defensive colour rules:** `.view` sets `color: var(--text-primary)`; buttons, selects, inputs and table cells inside views inherit it via a zero-specificity `:where()` rule (component rules still win); `option`/`optgroup` get the surface background; `:root` declares `color-scheme: dark` so native popups and scrollbars render dark; SVG text gets its fill from `.dash svg text`.
- **`--text-muted` lightened** from #8b8a96 to #9d9ca9: the old value was 4.1:1 on the "geen data" bar (NO_DATA_COLOR at 35 % over the card), below AA for 10 px text. Now ≥ 4.5:1 on every surface, checked in the test.
